# MVP — 정의문으로 못 박기

## 목적

네 단계의 산출물을 하나의 결정으로 압축한다. 이 파일 하나만 읽으면 "무엇을, 왜, 어디까지" 만드는지가 통해야 한다.

## 입력

- `01-personas.md` · `02-journeys.md` · `03-quadrant.md` · `04-arrow.md`
- 빠진 단계가 있으면 그 스킬부터 실행한다. 없는 산출물을 상상으로 메우지 않는다.

## 워크플로우

1. **정의문을 템플릿으로 쓴다.**
   ```
   <주 페르소나>의 <J의 주 바닥 구간 문제>를,
   <A에서 바꾼 화살표: 무엇이 누구에게 닿게 되는지>로 바꾼다.
   ```
   - 예: "맡긴 주인의 모르는 시간을, 시터가 남기는 사진 세 장과 산책 경로가 실시간으로 닿는 리포트로 바꾼다."
   - 검수: 정의문에 P의 페르소나 이름, J의 바닥, A의 화살표가 전부 등장하는가. 하나라도 빠지면 다시 쓴다.
   - 기능 이름이 아니라 "무엇이 어떻게 달라지는지"로 쓴다. 구현 수단(사진 세 장 같은 구체)은 핵심 수단일 때만 넣는다.
2. **포함 범위를 적는다.** Q의 채택 후보 + 그걸 지탱하는 최소 기본형(예: 예약·결제는 기본형으로). 항목마다 "정의문의 어느 부분을 담당하는지"를 붙인다.
3. **제외 범위를 적는다.** Q의 2차 목록 + A에서 "그대로 두는 구간". "안 만든다"가 아니라 "이번엔 아니다"로 — 각 항목에 2차로 미루는 이유를 유지한다.
4. **성공 신호를 1개 정한다.** 정의문이 맞았는지 확인할 관찰 가능한 신호. 수치 목표를 지어내지 말고 행동 신호로 쓴다 (예: "첫 리포트를 받은 주인의 재예약률이 그렇지 않은 주인보다 높다" — 방향만, 수치는 실측 후).
5. **전 단계와 정합성 검사를 한다.** 정의문의 페르소나=P, 바닥=J, 기능=Q, 화살표=A와 글자 그대로 대조한다. 어긋나면 어느 단계가 기준인지 사용자에게 확인한다.
6. **추천 MVP 기획을 마지막에 붙인다.** 정의문을 "만드는 순서"로 번역한다.
   - 순서는 **A에서 바꾼 화살표 구간부터**다. MVP의 심장인 그 구간을 1단계로 만들고, 예약·결제 같은 기본형은 그 다음, 채택 기능의 나머지는 마지막에 붙인다.
   - 각 단계에 완료 판정을 단다 ("무엇이 되면 끝인가"를 관찰 가능한 상태로).
   - 핵심 화면·흐름은 포함 목록을 화면 단위로 푼 것만 적는다. 포함에 없는 화면을 새로 만들지 않는다.
   - 플랫폼·기술 스택처럼 산출물에 없는 결정은 지어내지 않고 「착수 전 결정할 것」에 올린다.

## 산출물 계약 — `05-mvp.md`

```markdown
# MVP — <아이디어명>

## 정의문
<한 문장>

## 포함 (첫 버전)
- <항목> — 정의문의 <부분> 담당

## 제외 (2차)
- <항목> — <미루는 이유>

## 성공 신호
<관찰 가능한 행동 신호 1개>

## 근거 추적
- 페르소나: <이름> (01) / 바닥: <구간> (02) / 채택: <기능> (03) / 화살표: <구간> (04)

## 추천 MVP 기획
### 만들 순서
1. <바꾼 화살표 구간> — <무엇을 만드는가> / 완료 판정: <관찰 가능한 상태>
2. <기본형> — ...
3. <남은 채택 기능> — ...

### 핵심 화면·흐름
- <화면> — 정의문의 <부분> 담당

### 착수 전 결정할 것
- <산출물에 없어 정해야 하는 것> (없으면 "없음")
```

## 품질 게이트

- 정의문이 2문장 이상이면 실패. 쉼표로 이어서 한 문장으로 만든다.
- 포함에 Q 채택에 없던 기능이 끼어 있으면 실패.
- 성공 신호가 "매출·다운로드 수" 같은 결과 지표뿐이면 실패 — 사용자가 실제로 겪는 변화(행동 신호)로 바꾼다.
- 추천 기획의 만들 순서 1번이 바꾼 화살표 구간이 아니면 실패. 포함 목록에 없는 기능·화면이 기획에 등장해도 실패.

## 규칙

- 정의문에 수식어를 쌓지 않는다 ("혁신적인", "스마트한" 금지). 주어·대상·변화가 읽히면 된다.
- 이 문서는 기획의 끝이자 개발 착수의 시작이다. 다음 행동(프로토타입·개발 스킬로의 핸드오프)이 가능하도록 파일 경로를 명시해 마친다.
