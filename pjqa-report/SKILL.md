# pjqa-report — 한 파일짜리 종합 보고서

## 목적

여섯 개 마크다운 파일로 흩어진 도출 결과를, **파일 하나로 열고 단계별로 선택해 보는** HTML 보고서로 묶는다. 받는 사람이 마크다운을 몰라도 정의문부터 근거까지 한 번에 읽을 수 있게 하는 것이 목적이다.

## 입력

- `pjqa-projects/<slug>/` 의 00~05 산출물. 하나라도 없으면:
  - 아이디어만 주어진 경우 → `pjqa` 오케스트레이터로 전 과정을 먼저 실행한다.
  - 프로젝트 폴더가 있는데 일부만 있으면 → 빠진 단계를 먼저 채우고 진행한다.

## 페이지 구성 (고정)

좌측 사이드바(모바일은 상단 탭)로 페이지를 선택한다. 순서는 도출 순서를 따른다.

1. **개요** — 아이디어 한 줄, MVP 정의문(대형), 진짜 문제 한 문장, 핵심 카드 3장(주인공 수·채택 기능·바꾼 화살표), 단계 요약
2. **P 페르소나** — 주인공 카드 (각 카드: 정체성·하는 일·대표 불편·비결제 주인공 배지)
3. **J 여정** — 감정 곡선 SVG (공통 단계 축, 전 페르소나 겹침), 바닥 구간 음영, 접점 표시, 진짜 문제 배너
4. **Q 사분면** — 사분면 박스 (왼쪽 위 채택 강조, 나머지는 흐리게), 채택/2차/탈락 목록
5. **A 화살표** — AS-IS 흐름 카드 + 화살표, 바꾼 화살표만 앰버 강조, 그대로 두는 구간, TO-BE 대조
6. **MVP** — 정의문, 포함/제외 2열, 성공 신호, 근거 추적
7. **추천 기획** — 만들 순서 타임라인 (단계별 완료 판정), 핵심 화면, 착수 전 결정할 것

## 디자인 규격 (고정)

- 단일 파일. 외부 리소스 0개 — CSS·JS 인라인, 폰트는 시스템 스택(`-apple-system, 'Malgun Gothic', sans-serif` 계열). 인터넷 없이 열려야 한다.
- 다크 테마: 배경 `#0d1117`, 카드 `#11161d`, 경계 `#2a3242`, 본문 `#e9eef5`, 보조 `#9aa7b4`.
- 의미 색 고정: 페르소나 색은 등장 순서대로 민트 `#2fd4b6` · 오렌지 `#ff9f43` · 틸 `#4dd0e1` · 보라 `#a55eea` — 전 페이지에서 같은 사람을 같은 색으로. 문제/바닥은 핑크 `#ff6b9d`, 바꾼 화살표·MVP 강조는 앰버 `#ffc24b`.
- 본문 최소 15px, 정의문은 28px 이상 굵게. 작은 글자로 빽빽하게 채우지 않는다.

## 제작 방법

1. 동봉 빌더 실행을 기본으로 한다:
   ```bash
   python3 <이 스킬 폴더>/scripts/build_report.py <프로젝트 폴더>
   ```
   산출물 계약(각 스킬의 형식)대로 쓰인 프로젝트면 `report.html`이 바로 생성된다.
2. 빌더가 비우거나 잘못 채운 페이지가 있으면, 그 페이지만 위 구성·규격에 맞춰 손으로 고친다. 고친 뒤에는 반드시 브라우저 스크린샷으로 전 페이지를 확인한다.
3. 완성본 위치: `<프로젝트 폴더>/report.html`.

## 운영 규칙

1. **산출물에 없는 내용을 보고서에 추가하지 않는다.** 요약·압축은 되지만 새 주장·새 수치·새 기능은 금지. 비어 있는 항목은 비어 있다고 표시한다.
2. 여정 곡선의 높낮이는 산출물의 감정 표기(높음/중간/낮음/회복)를 그대로 옮긴다. 곡선을 더 극적으로 만들려고 값을 바꾸지 않는다.
3. 사분면 배치는 산출물의 위치 표기를 그대로 따른다.
4. 완료 보고에는 `report.html` 경로와 페이지 수, 빌더가 비운 페이지가 있었는지를 포함한다.
