ai-trading-agent

잠자는 사이에도 24시간 도는 코인 시장에서, 급등락이 오면 미리 정해둔 대응을 대신 실행하고 알려주는 AI 트레이딩 에이전트

MVP 정의문
자는 투자자의 모르는 밤을, 규칙대로 실행한 전 과정이 아침에 리플레이로 검증되는 기록으로 바꾼다.
진짜 문제
급등락 대응 자체는 규칙 실행으로 해결된다. 남는 문제는 위임의 검증이다. 규칙대로 실행했는지 보여 주는 기록이 없으면, 자동 실행은 맡기는 것이 아니라 방치하는 것이다.
주인공
맡기는 투자자 · 실행하는 에이전트 · 주문을 받는 거래소
채택 기능 (왼쪽 위)
실행 전 과정 리플레이
바꾸는 화살표
3 → 4 구간: "놓친 급등락이 아침의 손실 확인이 되는 구간"을 바꾼다. 급등락이 오면 에이전트가 정해진 규칙대로 실행하고 전 과정을 기록한다. 아침에 투자자가 맞는 것은 손실 통보가 아니라 검증할 기록이다.

  • · 거래소 고객센터 — 체결 실패를 사후에 해명하는 상대

MVP — 정의

정의문
자는 투자자의 모르는 밤을, 규칙대로 실행한 전 과정이 아침에 리플레이로 검증되는 기록으로 바꾼다.
포함 (첫 버전)
  • · 실행 전 과정 리플레이 — 체결 실패·부분 체결·범위 차단으로 막힌 주문까지 전부 기록한다 (성공만 기록하면 검증이 반쪽이다). 정의문의 "검증되는 기록" 담당
  • · 규칙 범위 밖 주문 차단 + 자동 정지 — 범위 밖 주문은 거부하고, 하루 손실 한도 초과·주문 연속 실패 시 에이전트가 스스로 멈추고 알린다. 정의문의 "규칙대로"를 보장하는 장치
  • · 규칙 실행 기본형 — 손절·익절 조건 실행 + 거래소 1곳 연동 (출금 권한이 있는 API 키는 연결을 거부한다), 정의문의 "실행" 담당
제외 (2차)
  • · 모의 실행 모드 — 실거래 전 실시간 시세로 가짜 실행. 맡기기 전 불안을 줄이는 데 백테스트보다 먼저다
  • · 규칙 백테스트 사전 검증 — 실행 기록 검증이 먼저
  • · 전략 자동 생성 — 책임·검증 체계 선행 필요
  • · 급등락 즉시 깨우기 — 위임의 목적과 충돌
  • · 다중 거래소 연동 — 첫 버전은 1곳으로 검증
  • · 매매 기록 내보내기 — 세금 신고용, 작지만 사용자가 반드시 찾는 기능
성공 신호
첫 급등락이 지난 아침, 투자자가 리플레이를 끝까지 확인한 뒤 에이전트를 끄지 않고 다음 밤에도 그대로 맡기는가.
근거 추적 — - 페르소나: 맡기는 투자자 (01) / 바닥: 맡겼지만 확인할 방법이 없는 구간 (02) / 채택: 실행 리플레이·범위 차단 (03) / 화살표: 급등락→아침 구간 (04)

추천 MVP 기획

플랫폼
  • · 형태: 모바일 앱 (사용자 접점) + 서버 에이전트 (감시·실행) — 근거: 핵심 접점이 아침 푸시 알림과 즉시 정지라 앱이 맞고, 24시간 감시와 실행은 폰이 꺼져 있어도 돌아야 해서 서버가 맡는다
  • · 구성: 앱 — 규칙 설정·리플레이 확인 / 서버 — 시세 감시·주문 실행·전 과정 기록

만들 순서

1
실행 기록 리플레이 (바꾼 화살표 구간)
발동·주문·체결은 물론 실패·차단까지 타임라인으로 기록하고 리플레이 화면으로 재생
완료 판정 — 밤사이 실행 1건이 처음부터 끝까지 리플레이된다
2
규칙 실행 기본형 + 범위 차단·자동 정지
규칙 설정 화면과 에이전트 상태 화면 포함
완료 판정 — 정한 조건에서만 주문이 나가고 범위 밖 주문은 차단된다
3
거래소 연동 (1곳) + 아침 요약
연동 화면과 홈 요약, 아침 푸시
완료 판정 — 아침에 밤사이 요약 푸시가 도착한다
핵심 화면·흐름
  • · 홈 (밤사이 요약) — 목적: 아침 10초 안에 밤사이 결과를 파악한다 / 구성: 실행 건수, 발동한 규칙, 차단·실패 건수 배지, 밤사이 손익 범위 / 동작: 요약 카드를 누르면 해당 리플레이로 이동하고, 발동이 없던 밤은 "발동 없음"으로 표시한다
  • · 실행 리플레이 — 목적: 실행 1건을 처음부터 끝까지 검증한다 / 구성: 타임라인 (발동 시각·당시 시세·주문·체결·범위 검사 결과, 실패·차단 구간도 같은 줄에 표시), 발동 이유 하이라이트 / 동작: 구간 이동과 배속 재생, 이상 구간만 골라 보기
  • · 규칙 설정 — 목적: 손절·익절 조건과 권한 범위를 정한다 / 구성: 조건 입력 (가격·등락률), 1회 최대 금액·하루 한도, 적용 시간대 / 동작: 저장 전에 범위 검사를 미리 보여 주고, 범위를 벗어난 값은 저장 자체가 막힌다
  • · 에이전트 상태 — 목적: 지금 감시 중인지 알고, 즉시 멈출 수 있다 / 구성: 상태 표시 (감시 중·자동 정지·수동 정지), 비상 정지 버튼, 오늘 손실 한도 진행, 거래소 연동 상태 / 동작: 정지를 누르면 대기 주문 취소와 감시 중단이 즉시 일어나고, 자동 정지 조건에 닿아도 같은 방식으로 멈추고 알린다
  • · 거래소 연동 — 목적: 거래소 1곳을 안전하게 연결한다 / 구성: 거래소 선택, API 키 입력, 권한 단계 표시 (조회 → 매매) / 동작: 잔고 조회 테스트가 성공해야 매매가 활성화되고, 출금 권한이 감지된 키는 연결 자체를 거부한다
착수 전 결정할 것
  • · 본인 계좌 전용 명시와 책임 고지 문구 (타인 자금을 굴리는 형태가 되면 규제 영역이 달라진다)
  • · 첫 연동 거래소
  • · 규칙 표현 범위 (가격 조건만 / 지표 조건 포함)
사용자 흐름 — 거래소 연동 → 규칙 설정 → 감시 시작 → 밤사이 발동 시 실행·기록 → 아침 요약 푸시 → 리플레이 검증 → 규칙을 고치거나 그대로 둔다
