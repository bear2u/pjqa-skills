# Q — Quadrant, 왼쪽 위만 남기기

## 목적

펼친 것을 줄이는 단계. 기준은 취향이 아니라 두 축 — **영향**(J에서 찾은 바닥을 얼마나 메우는가)과 **난이도**(얼마나 빨리 만들 수 있는가) — 뿐이다.

## 입력

- `02-journeys.md` (특히 진짜 문제 한 문장과 바닥 구간)
- 없으면 사용자에게 "풀려는 문제 한 문장"을 먼저 받는다. 문제 없이 기능부터 나열하지 않는다.

## 워크플로우

1. **후보를 고통점에서만 도출한다.** J의 각 바닥·고통마다 "이걸 메우는 기능"을 1~3개씩 뽑는다. 총 5~8개.
   - 어느 고통과도 연결되지 않는 기능은 후보에 올리지 않는다. 떠오르면 「탈락」에 이유와 함께 기록만 한다 (예: 쇼핑·커뮤니티 같은 붙이기 쉬운 것들).
2. **사분면에 배치한다.**
   - 세로축: 영향 큼(위) / 작음(아래). 영향 = 주 바닥을 메우는 정도.
   - 가로축: 쉬움(왼쪽) / 어려움(오른쪽). 난이도 = 데이터·연동·운영 부담 포함.
   - 각 후보에 배치 근거를 한 줄씩 붙인다. 근거 없는 배치는 없다.
3. **왼쪽 위만 채택한다.** 1~3개. 4개 이상이면 영향이 가장 큰 순으로 자른다 — MVP는 작아야 한다.
4. **나머지는 명시적으로 미룬다.** 오른쪽 위(영향 크지만 어려움)와 아래쪽 전부를 「2차」 목록으로 옮기고, 각각 "왜 지금 아닌지"를 한 줄로 적는다. 삭제가 아니라 연기다.
5. **채택 후보를 진짜 문제 문장과 대조한다.** 채택된 기능이 진짜 문제를 직접 건드리는가? 아니면 Q를 다시 한다.

## 산출물 계약 — `03-quadrant.md`

```markdown
# 사분면 — <아이디어명>

## 후보 배치
| 후보 | 위치 | 근거 |
| ... | 왼쪽 위 / 오른쪽 위 / 아래 | 한 줄 |

## 채택 (왼쪽 위)
- <기능> — <주 바닥의 어느 부분을 메우는가>

## 2차로 미룸
- <기능> — <왜 지금 아닌지>

## 탈락
- <기능> — <어느 고통과도 연결되지 않음 등>
```

## 품질 게이트

- 후보가 고통점과 연결되지 않은 채 채택되면 실패.
- 채택이 0개면 실패 (바닥을 메우는 쉬운 게 없다는 건 J를 다시 봐야 한다는 신호), 4개 이상이어도 실패.
- "2차로 미룸"이 비어 있으면 실패. 아무것도 미루지 않는 계획은 우선순위가 없는 것이다.

## 규칙

- 난이도를 개발 기간만으로 재지 않는다. 외부 연동, 정산·법규, 운영 인력 같은 숨은 비용을 근거에 포함한다.
- 유행 기능( AI 챗봇, 커뮤니티, 쇼핑)을 관성으로 넣지 않는다. 고통점 연결이 없으면 탈락이다.
