# pjqa-skills

아이디어를 MVP로 도출하는 공식 **PJQA**를 에이전트 스킬로 구현한 스위트입니다.

```
아이디어 한 줄
  → P  Persona   펼치기     주인공을 빠짐없이 펼친다
  → J  Journey   겹쳐 보기  여정을 겹쳐 감정의 바닥을 찾는다
  → Q  Quadrant  줄이기     왼쪽 위만 남기고 나머지는 미룬다
  → A  Arrow     바꾸기     AS-IS 흐름에서 화살표 하나만 바꾼다
  → MVP 정의문 + 포함/제외 범위 + 성공 신호
```

핵심 원칙은 세 가지입니다.

1. **바닥에서 시작한다.** 기능 목록이 아니라, 사용자 여정에서 감정이 가장 가라앉는 "구간"이 진짜 문제다.
2. **하나만 바꾼다.** 기존 흐름(AS-IS)의 화살표 딱 하나를 바꾸는 것이 MVP다. 나머지는 기존 방식을 그대로 둔다.
3. **미루는 것도 결정이다.** 채택하지 않은 후보는 버리는 게 아니라 "2차"로 명시적으로 미룬다.

## 스킬 구성

| 스킬 | 역할 | 산출물 |
|---|---|---|
| `pjqa` | 오케스트레이터 — 전 과정을 순서대로 실행, 단계마다 사용자 확인 게이트 | 프로젝트 폴더 전체 |
| `pjqa-persona` | P — 주인공 도출 (결제하지 않아도 설계의 중심인 존재 포함) | `01-personas.md` |
| `pjqa-journey` | J — 여정 겹치기, 바닥·접점 특정, 진짜 문제 한 문장 | `02-journeys.md` |
| `pjqa-quadrant` | Q — 후보를 영향×난이도로 나눠 왼쪽 위만 채택 | `03-quadrant.md` |
| `pjqa-arrow` | A — AS-IS 흐름에서 바꿀 화살표 1개 선정 | `04-arrow.md` |
| `pjqa-mvp` | 종합 — MVP 정의문·포함/제외·성공 신호·추천 MVP 기획 | `05-mvp.md` |

단계 스킬은 단독 실행도 됩니다. 앞 단계 산출물이 있으면 거기서 이어서 시작합니다.

## 설치

Claude Code 기준:

```bash
git clone https://github.com/bear2u/pjqa-skills.git
cp -r pjqa-skills/pjqa* ~/.claude/skills/
```

## 사용법

```
PJQA로 도출해줘: 출근길에 읽는 3분 경제 뉴스 앱
```

작업 폴더 `pjqa-projects/<아이디어명>/`에 단계별 파일이 쌓입니다. 중단해도 파일만으로 이어서 진행할 수 있습니다. 단계마다 산출물을 보여주고 확인을 받으며, "끝까지 자동으로"라고 하면 게이트 없이 완주합니다.

## 예시

- [`examples/petcare/`](examples/petcare/) — 반려동물 돌봄 매칭 앱. 주인·시터·**반려동물**(결제하지 않지만 설계의 중심) 세 주인공의 여정이 겹치는 지점에서 "확인 방법이 없는 시간"이라는 진짜 문제를 찾고, 화살표 하나(돌봄 중 기록이 닿는 구간)를 바꿔 MVP를 정의한 전 과정입니다.
- [`examples/hospital-escort/`](examples/hospital-escort/) — 부모님 병원 동행 매칭. 이 스킬 스위트 자체를 실행해 검증한 도그푸딩 산출물입니다.
