# PJQA — 아이디어를 MVP로 도출하는 공식

## 개요

아이디어 도출 = 그림 네 장 + 정의 한 문장.

- **P 펼치기** — 주인공을 빠짐없이 펼친다
- **J 겹쳐 보기** — 여정을 겹쳐 감정의 바닥을 찾는다
- **Q 줄이기** — 사분면 왼쪽 위만 남긴다
- **A 바꾸기** — 지금 흐름에서 화살표 하나만 바꾼다
- **MVP** — 정의문 한 문장 + 포함/제외 + 성공 신호

## 작업 규약

- 작업 폴더: `pjqa-projects/<slug>/` (slug는 아이디어를 짧은 영문/한글 이름으로)
- 단계별 산출물 파일:
  - `00-brief.md` — 아이디어 한 줄 + 배경 + 제약 (사용자가 준 정보만, 지어내지 않는다)
  - `01-personas.md` · `02-journeys.md` · `03-quadrant.md` · `04-arrow.md` · `05-mvp.md`
- 폴더가 이미 있으면 있는 파일까지 읽고 다음 단계부터 이어서 진행한다.

## 워크플로우

1. **브리프 확정.** 사용자에게서 아이디어 한 줄과 (있다면) 배경·제약을 받는다. 부족하면 딱 하나만 묻는다: "누구를 위한 건가요?" 그래도 없으면 가정을 `00-brief.md`에 「가정」으로 명시하고 진행한다.
2. **단계 실행.** 아래 순서로 단계 스킬을 실행한다. 각 스킬의 품질 게이트를 통과하지 못하면 그 단계에서 고치고 넘어간다.
   1. `pjqa-persona` → `01-personas.md`
   2. `pjqa-journey` → `02-journeys.md`
   3. `pjqa-quadrant` → `03-quadrant.md`
   4. `pjqa-arrow` → `04-arrow.md`
   5. `pjqa-mvp` → `05-mvp.md`
3. **단계 게이트.** 각 단계가 끝나면 사용자에게 보여준다: 산출물 핵심 요약 3줄 이내 + 다음 단계에서 달라질 수 있는 결정 지점. 사용자가 수정을 말하면 그 단계를 고친 뒤 진행한다.
   - 사용자가 처음에 "끝까지 자동으로"라고 했으면 게이트 없이 완주하고 마지막에 전체를 보고한다.
   - 사용자가 특정 단계만 원하면(예: "페르소나까지만") 거기서 멈춘다.
4. **완료 보고.** `05-mvp.md`의 정의문을 본문에 그대로 인용하고, 추천 MVP 기획의 "만들 순서"를 요약해 전한다. 파일 경로 목록과 "2차로 미룬 것"도 함께 전한다.

## 운영 규칙

1. 앞 단계 산출물을 뒤 단계에서 임의로 바꾸지 않는다. 모순이 발견되면 그 단계를 다시 열고 사용자에게 알린다.
2. 수치·시장 규모·경쟁사 같은 외부 사실을 지어내지 않는다. 필요하면 「미확인」으로 표시한다.
3. 각 단계의 핵심 규칙을 건너뛰지 않는다. 특히: P의 비결제 주인공 검사, J의 "바닥은 구간" 규칙, Q의 "후보=고통점 도출" 규칙, A의 "화살표 정확히 1개" 규칙.
4. 최종 산출물은 파일이다. 채팅 답변은 요약만 하고, 전체 내용은 파일에 둔다.

## 산출물 계약

완료 시점에 `pjqa-projects/<slug>/`에 00~05 여섯 파일이 모두 있고, `05-mvp.md`에는 ① MVP 정의문 한 문장 ② 포함 목록 ③ 제외(2차) 목록 ④ 성공 신호 1개 ⑤ 추천 MVP 기획(만들 순서·핵심 화면·착수 전 결정할 것)이 들어 있어야 한다. 하나라도 빠지면 완료로 보고하지 않는다.
